# 大肥鱼 1.3.1 · QQ 登录修复

日期：2026-11-11。界面与维护：mzbgq。版本 1.3.1 / 100301，沿用原应用 ID 和签名。

## 最终修改

QQ 程序副本改为真实文件复制。原实现使用 guest 硬链接，而 PRoot 启用 `--link2symlink` 后会转为软链接，Electron 可能由旧目录解析程序入口。新版复制布局为第 2 版，自动重建旧缓存、还原原始 QQ 入口并省略 NapCat 入口，保留源镜像与账号 HOME。使用真实 ELF 验证了软链接场景下旧路径解析，以及新版独立路径、旧缓存修复和源文件保持不变。

登录画面改为安卓原生位图 Canvas，直接连接本机有密码认证的 x11vnc。QQ 登录页不创建 WebView，不使用网页画面作为日常显示。受限 RFB 适配器只连接固定本机端口，支持所带服务端的认证、RAW 像素、点击、拖动和键盘事件。格式参考随包 noVNC 1.3.0，未复制第三方客户端实现。

原生画面位于实底容器中，不经过玻璃折射。放大后可以拖动位置；键盘在安卓原生对话框输入后发往 QQ 当前输入框。刷新或离开页面关闭对应画面连接，QQ 和 SnowLuma 继续由后台服务管理。图像解码在后台执行，界面状态在主线程发布；断开后清除旧画面。

## 本轮实际检查

- QQ 副本检查通过：原始入口、源文件不变、排除 NapCat、重复准备、版本变化、旧软链接缓存迁移，以及实际 ELF 执行路径。
- **Android 13 / API 33 原生显示场景通过，32.81 秒。** 使用认证 RFB 测试服务器发送真实协议帧，在安卓截取并检查三个画面的红、绿像素：首次打开、刷新、离开后重新进入。场景还执行了点击与键盘文本传输。记录见 `validation/qq-view-android-1.3.1.json`、`validation/qq-native-instrumentation-1.3.1.txt` 和对应 PNG。它不是 QQ 账号登录测试。
- 较早的 WebView 方案在无硬件加速模拟器中出现 System UI ANR 与 WebView 原生 SIGTRAP，没有计为通过；最终登录显示已替换为原生 Canvas。原生方案首次回归还发现 UI 线程更新问题，修复后上述场景通过。
- 保留的高级浏览器页面在移动 Chromium 中通过：认证帧像素、触摸、Unicode 输入、缩放、单指拖动、刷新、模块失败提示及恢复。该结果不冒充最终安卓显示检查。
- APK 的实际版本、签名和内置资源核对以 `validation/apk-verification.json`、`validation/delivery.json` 为准。
